# 0005 — Text and languages

- **Status:** accepted
- **Date:** 2026-11-20

## Decision

Two languages, English and Spanish, with English as the source of truth. `src/i18n/en.ts` defines the
dictionary and its type; `src/i18n/es.ts` is typed against it, so a missing or extra key fails `tsc`.
Components read text through `useT()` and never contain a literal sentence. Strings with values use typed
interpolation (`t('posts.count', { count })`).

The active locale is a `LocaleProvider` value: initial value from `localStorage`, then the browser
language if it is Spanish, otherwise English. Changing it updates `<html lang>` and re-renders the text;
it never resets selection or a draft.

## Why

A dictionary that is a type costs nothing at runtime and turns "forgot to translate" into a compile
error. Keeping the switch state-only (no reload) is what makes the draft survive.

## Rejected

- `react-i18next` or `react-intl`: correct for a product with plural rules and ICU; here they add a
  dependency to do what one context and one typed object do.
- Strings next to the component: the Spanish version would drift from the English one silently.

## Enforced by

`scripts/ratchet/rules.d/no-literal-ui-text.sh`; the `es.ts` type check.
